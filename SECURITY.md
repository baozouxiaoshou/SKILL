# Security Policy / 安全策略

### English
If you discover a security vulnerability in this project, please report it privately.

### 中文
如果你发现安全漏洞，请私下报告。

---

## Supported Versions / 支持的版本

| Version | Supported          |
|---------|--------------------|
| 1.0.x   | ✅ Active support  |
| < 1.0   | ❌ No support     |

---

## Reporting a Vulnerability / 报告漏洞

### English
**Please do not report security vulnerabilities through public GitHub issues.**

Instead, please report them via email to: [security@your-domain.com](mailto:security@your-domain.com)

You should receive a response within 48 hours. If for some reason you do not, please follow up via email.

Please include the following information:
- Type of vulnerability
- Full path of source file(s) related to the vulnerability
- Location of the affected source code (tag/branch/commit or direct URL)
- Step-by-step instructions to reproduce the issue
- Proof-of-concept or exploit code (if possible)
- Impact of the issue

### 中文
**请勿通过公开 GitHub issue 报告安全漏洞。**

请通过邮件报告：[security@your-domain.com](mailto:security@your-domain.com)

我们会在 48 小时内回复。如果没收到，请通过邮件跟进。

请提供：
- 漏洞类型
- 相关源文件的完整路径
- 受影响代码的位置（tag/分支/提交或直接 URL）
- 重现步骤
- 概念验证代码（如可能）
- 漏洞影响

---

## Response Process / 响应流程

1. **Acknowledgment** / 确认 - We will acknowledge receipt within 48 hours
2. **Investigation** / 调查 - We will investigate and report back within 7 days
3. **Fix** / 修复 - We will work on a fix and coordinate disclosure
4. **Disclosure** / 披露 - We will publicly disclose after the fix is released

---

## Notes on This Skill

This Skill is primarily:
- **Documentation** (Markdown files)
- **Python scripts** (for Figma/Lark integration)
- **Shell scripts** (for installation/packaging)

No production code is executed that handles user data directly. All scripts run locally.

本 Skill 主要包含：
