# 完整案例（Examples）

> 两个完整案例：C 端 + B 端轻量，覆盖两类典型场景。

# 案例 1：C 端 —— 健身 App AI 训练计划推荐

## 场景判断
- **类型**：C 端
- **判断依据**：用户为健身爱好者（个人消费者）、核心痛点是"不知道练什么"（体验问题）
- **输出侧重**：体验、留存、增长指标

## 输入需求
> 健身 App 现有大量训练视频，用户反馈"不知道从哪个开始"、新人流失严重。现在要做"AI 训练计划推荐"，根据用户水平/目标/设备推荐个性化训练计划。

## 核心 Persona
1. **小胖**（健身小白）：28岁程序员，痛点是不知练什么、怕受伤
2. **Lisa**（进阶塑形）：32岁职场妈妈，痛点是时间碎片化
3. **阿龙**（健身进阶）：35岁资深跑者，缺乏高级内容

## 6 个用户故事（精选）

### STORY-1：3 步引导问卷
作为【小胖】，我想要【首次进入 App 用 3 个简单问题确定训练水平】，以便【系统能推荐适合我的训练计划】。
- P0，3 点
- AC：3 步、≤10s/步、可重新填写

### STORY-2：生成个性化训练计划
作为【小胖】，我想要【完成问卷后立即看到一份 30 天的训练计划】，以便【不用自己研究要练什么】。
- P0，8 点
- AC：1.5s 内生成、冷启动规则引擎兜底、个性化基于历史

### STORY-3：每日智能推荐课
作为【小胖】，我想要【首页直接看到今天该练的内容】，以便【不用翻找视频】。
- P0，8 点
- AC：首屏 60% 按钮、休息日轻推荐、动态调整难度

### STORY-4：训练完成与正向反馈
作为【小胖】，我想要【训练完后看到温暖的总结】，以便【感受到进步的成就感】。
- P1，5 点
- AC：动画 + 进度、里程碑奖励、负面话术兜底

### STORY-5：动态难度调整
作为【Lisa】，我想要【感觉太轻松或太难时一键换难度】，以便【保持合适的挑战强度】。
- P1，5 点
- AC：太简单 +10%、太难 -10%、智能调整无反馈场景

### STORY-6：30 天里程碑与进阶路径
作为【小胖】，我想要【完成 30 天计划后看到清晰的进阶路径】。
- P2，8 点
- AC：庆祝动画、3 个进阶计划、横向探索

## 关键指标

| 指标 | 目标 |
|------|------|
| 30 日留存率 | +5% |
| 计划完成率 | ≥40% |
| 首课完成率 | ≥70% |
| 反馈按钮点击率 | ≥30% |

## AB 实验
- 问卷长度（3 步 vs 5 步）
- 推荐精度（个性化 vs 默认）
- 反馈机制（显式 vs 隐式）

# 案例 2：B 端轻量 —— RAS 模块双语录入

## 场景判断
- **类型**：B 端轻量
- **判断依据**：用户为企业合规专员（专业人士）、核心痛点是双语录入效率 + 翻译准确性、有合规和审计追溯要求
- **输出侧重**：合规、准确、效率

## 输入需求
> 在 RAS 模块的异常分析、整改措施填报等关键录入环节，集成 HPS 实时翻译引擎。支持中英双语录入和勘误功能，关键字段自动呈现双语，确保格式统一。

## 核心 Persona
1. **小陈**（中文母语合规专员）：28岁，痛点是专业术语翻译不准
2. **John**（外籍风控分析师）：38岁，痛点是中文报告撰写慢
3. **Ms. Wang**（监管对接员）：35岁，痛点是手工维护双语易出错

## 6 个用户故事（精选）

### STORY-1：选择输入语言
作为【小陈】，我想要【在新建录入时选择主输入语言】，以便【从一开始就用熟悉的语言录入】。
- P0，2 点
- AC：默认上次偏好、切换需二次确认

### STORY-2：关键字段实时双语生成
作为【小陈】，我想要【录入三个关键字段时另一语种版本同步生成】，以便【无需重复录入】。
- P0，8 点
- AC：1.5s 延迟触发、流式渲染、术语库支撑

### STORY-3：双语格式统一与对照展示
作为【小陈】，我想要【双语版本以清晰的对照格式展示】，以便【提交时不需要再排版】。
- P0，5 点
- AC：表格对照、缺失提示、PDF/Word 导出

### STORY-4：勘误功能
作为【John】，我想要【在 AI 翻译有误时手动勘误】，以便【确保双语版本准确】。
- P0，5 点
- AC：原文对照编辑、版本快照、自动学习术语库

### STORY-5：版本快照与回溯
作为【Ms. Wang】，我想要【提交后的双语报告有版本快照】，以便【应对监管复核】。
- P1，5 点
- AC：自动快照、版本对比、导出历史版本

### STORY-6：批量翻译与多语言扩展
作为【Ms. Wang】，我想要【对历史单语报告进行批量翻译】。
- P2，8 点
- AC：批量入口、异步队列、失败重试、多语言插件化

## 关键指标

| 指标 | 目标 |
|------|------|
| 双语报告完成率 | ≥99% |
| 翻译成功率 | ≥98% |
| 翻译平均延迟 | ≤2s/字段 |
| 勘误字段占比 | ≤15% |
| 术语库命中率 | ≥70% |

## 合规与审计设计

| 设计项 | 说明 |
|--------|------|
| **版本快照** | 每次提交自动生成不可修改快照 |
| **审计日志** | 完整记录操作人、时间、内容 |
| **术语库** | 后台管理 + 自动学习机制 |
| **权限边界** | 按角色严格隔离，敏感操作告警 |
| **数据脱敏** | 对外导出自动脱敏 |
| **多语言格式** | 中英/中日/中越插件化扩展 |

## AB 实验
- 翻译延迟 1.5s vs 2.5s（准确性 vs 体验）
- 术语库自动学习 vs 手动审核
- 流式 vs 一次性翻译

# 场景识别指南

## 何时用 C 端方法论
✅ 用户是普通消费者
✅ 痛点是体验、情感、便捷
✅ 关键是留存、增长、活跃
✅ 可考虑 AB 实验

## 何时用 B 端轻量方法论
✅ 用户是企业内专业人士
✅ 痛点是效率、准确、合规
✅ 必须有版本快照 / 审计追溯
✅ 涉及专业术语 / 双语录入

## 何时不用这个 Skill（需专用技能）
❌ 复杂业务建模（领域驱动 / BPMN）
❌ 跨系统架构设计
❌ 详细 RBAC 权限矩阵
❌ 完整 BABOK 业务分析

# 复用建议

## 复用到自己的项目
1. 复制 `prompts/system.md` 作为系统提示词
2. 复制 `templates/` 下需要的模板
3. 按本文件中的两个案例结构组织输出

## 调整方法
- 强化 C 端：在 `system.md` 中强调"用户情感"、增加"留存/增长指标"
- 强化 B 端：在 `system.md` 中强调"合规"、增加"版本快照 / 审计追溯"
- 场景混合：先按主场景输出，附录中补充次场景考量

# 反例：错误的混合输出

```
❌ "作为小陈（合规专员），我希望界面美观大方，以便用户用得开心"
   - Persona 是 B 端，但用户价值是 C 端语言
   
❌ "作为小胖（健身小白），我希望录入格式符合监管要求"
   - Persona 是 C 端，但合规是 B 端考量
```

正确做法：
- B 端 Persona：合规术语、效率导向
- C 端 Persona：情感化语言、留存导向
