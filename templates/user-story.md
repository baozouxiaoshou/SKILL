# 用户故事卡模板（User Story Card Template）

## Epic 层

```
【Epic 编号】EPIC-001
【Epic 名称】[模块名，如"用户激励体系"]
【业务目标】[为什么做这个，对北极指标的贡献]
【子故事数量】N 个
【预估总工作量】XX 个故事点
```

   - Given [...]
   - When [...]

## INVEST 质量检查

| 原则 | 检查问题 | 通过 |
|------|---------|------|
| **I**ndependent | 是否独立？可否单独发布？ | 0/1 |
| **N**egotiable | 是否留有协商空间（非死板合同）？ | 0/1 |
| **V**aluable | 用户能感知价值吗？ | 0/1 |
| **E**stimable | 团队能估算大小吗？ | 0/1 |
| **S**mall | 1 个 Sprint 能完成吗？ | 0/1 |
| **T**estable | 有明确验收标准吗？ | 0/1 |
| **总计** | ≥5 分才合格 | /5

## 好的故事 vs 坏的故事

### ❌ 坏故事
```
作为用户
我想要点击提交按钮
以便系统记录数据
```

**问题**：
- "作为用户" → 没指定 Persona
- "点击提交按钮" → 这是功能描述，不是用户故事
- "系统记录数据" → 技术价值，不是用户价值

### ✅ 好故事
```
作为【小李 - 25 岁职场新人】
我想要【在完成早起打卡后立即看到今天的鼓励语和成长积分】
以便【感受到坚持带来的正向反馈，增强继续打卡的意愿】
```

## 反模式检查
- [ ] 是否避免了"作为用户..."这种泛化角色？
- [ ] 用户价值是否清晰（不是技术价值）？
- [ ] 验收标准是否可以无歧义测试？
- [ ] 是否考虑了空/异常/边界场景？
- [ ] 故事粒度是否合适（1-8 个故事点）？
