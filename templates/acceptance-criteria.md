# 验收标准模板（Acceptance Criteria Template）

## Given-When-Then 三段式（通用）

### 模板
```
Given [前置条件 / Given 状态]
  And [其他前置条件]（可选）
When [用户操作 / 触发动作]
Then [预期结果 1]
  And [预期结果 2]（可选）
```

# B. B 端场景 AC 集合（新增）

### ✅ B-AC1：基本正向流程（同 C 端）

### ✅ B-AC2：双语/多语言场景
```
Given 用户已选择输入语言为中文
  And 系统接入了 HPS 翻译引擎
When 用户输入"风险概述"内容
Then 系统在 2 秒内生成英文版本
  And 双语版本格式对齐
  And 专业术语使用术语库翻译（而非字面翻译）
```

### ✅ B-AC3：版本快照与可追溯
```
Given 用户提交了双语报告 v1
When 系统存储
Then 自动生成版本快照（含双语、操作人、时间戳）
  And 快照不可修改
  And 后续任何修改生成新快照
  And 支持任意两版本 diff 对比
```

### ✅ B-AC4：审计追溯
```
Given 报告已被监管方查看
When 监管方提出复核要求
Then 系统能导出与提交版本完全一致的快照
  And 显示完整操作日志（谁在何时改了什么）
  And 关键字段修改有"修改痕迹"标记
```

### ✅ B-AC5：术语库支撑
```
Given 术语库已包含"洗钱风险"对应"money laundering risk"
When AI 翻译涉及该词
Then 使用术语库翻译（而非"washing money risk"等错误翻译）
  And 术语库可在后台维护
```

### ✅ B-AC6：合规校验
```
Given 用户录入异常分析时某些必填字段为空
When 用户点击提交
Then 系统阻断并高亮空字段
  And 提示"以下字段为合规必填项"
  And 不允许提交直到填完
```

### ✅ B-AC7：权限边界
```
Given 用户 A 是合规专员，用户 B 是其他部门员工
When A 查看某敏感异常分析
Then B 无权查看
  And 系统记录 A 的查看时间
  And 异常告警：用户 A 30 天内查看同份文档 > 5 次时触发审计告警
```

### ✅ B-AC8：勘误功能
```
Given AI 翻译"洗钱风险"为错误的字面翻译
When 用户点击"勘误"
Then 翻译字段变为可编辑
  And 显示原文便于校对
  And 提交勘误后保留原 AI 版本为 v1，勘误版为 v2
  And 询问是否将勘误结果加入术语库
```

### ✅ B-AC9：数据脱敏
```
Given 报告包含客户姓名、身份证号等敏感信息
When 导出对外版本
Then 自动脱敏（姓名→客户A、身份证号→110101********0011）
  And 脱敏规则可在后台配置
  And 提示"本文件为脱敏版，原版请通过授权流程获取"
```

### ✅ B-AC10：批量处理与异步
```
Given 用户提交了 50 份历史报告的双语翻译请求
When 提交
Then 进入异步队列
  And 实时显示进度（已完成 X/50）
  And 失败任务可一键重试
  And 总体进度通知（完成时 / 失败时）
```

## AC 编写要诀

### 1. AC 是验收，不是合同
- ✅ 可测试、可观察、可验证
- ❌ "界面美观"、"性能良好"

### 2. AC 要有粒度
- 一个 Story 拆 3-7 个 AC
- 每个 AC 聚焦一个点

### 3. AC 维度全覆盖（按场景）

#### C 端必含维度
| 维度 | 说明 |
|------|------|
| 功能正确性 | 主流程是否工作 |
| 边界处理 | 输入/输出的边界条件 |
| 异常处理 | 网络异常/服务异常/操作异常 |
| 权限控制 | 未登录/无权限的处理 |
| 性能 | 响应时间、加载时间 |
| 兼容性 | 设备/系统版本 |
| 数据 | 持久化、缓存、加密 |
| 状态 | 空状态、加载态、错误态 |

#### B 端必含维度（在 C 端基础上增加）
| 维度 | 说明 |
|------|------|
| **合规性** | 是否违反法规/行业标准 |
| **安全性** | 数据加密、访问控制 |
| **可追溯性** | 操作日志、版本快照 |
| **可审计性** | 监管检查、复核支持 |
| **协作性** | 多人协作、审批流 |
| **术语规范** | 专业术语统一性 |
| **脱敏** | 敏感数据处理 |
| **多语言** | 双语/多语言对照 |

### 4. 避免的写法
```
❌ "系统应该工作正常"
❌ "界面应该美观"
❌ "性能应该良好"
❌ "用户体验应该流畅"
✅ 改为可量化、可测试的语句
```
