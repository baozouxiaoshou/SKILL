# 状态机模板（State Diagram）

> 表达实体状态流转（订单、用户、合规事件）

---

## 模板 1：订单状态机

```mermaid
stateDiagram-v2
    [*] --> 待支付: 创建订单
    待支付 --> 已支付: 支付成功
    待支付 --> 已取消: 超时取消
    待支付 --> 已取消: 用户取消
    已支付 --> 已发货: 商家发货
    已支付 --> 退款中: 申请退款
    已发货 --> 已收货: 确认收货
    已发货 --> 退款中: 申请退款
    已收货 --> 已完成: 7 天后
    已收货 --> 退款中: 申请退款
    退款中 --> 已退款: 退款成功
    退款中 --> 已支付: 拒绝退款
    已取消 --> [*]
    已退款 --> [*]
    已完成 --> [*]
    
    note right of 已支付: 此时商家可以发货
    note right of 退款中: 进入售后流程
```

## 自检问题
- [ ] 状态是否穷尽（覆盖所有可能）？
- [ ] 状态间转换是否合理（无非法跳转）？
- [ ] 是否定义了起点和终点？
- [ ] 关键状态是否有注释？
- [ ] 时效要求是否标注？

## 实战技巧

### 命名规范
- 状态名简洁明确（"待支付"优于"等待用户完成支付"）
- 动作名清晰（"支付成功"而非"成功"）
- 状态机粒度一致（不要混"未支付"和"等待支付完成"）

### 颜色与强调
- 关键节点用颜色突出
- 终止状态加粗
- 时效/合规要求用 note 标注

### 组合状态
- 用 `state 父状态 { ... }` 表示嵌套状态
- 适合复杂的子状态（如订单的"售后"包含多个子状态）
